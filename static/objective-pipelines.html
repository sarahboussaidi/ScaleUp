Objective Pipelines

Each objective follows the same control loop: ingest, preprocess, run the task model, generate an explanation, score the result, and save the best selection. The page below maps that loop to the four objective-specific implementations already in the codebase.

Shared Pipeline

All objectives converge on the same registry and report files, so downstream pages can read the selected model, OCR engine, or summarization strategy without hardcoding paths.

1. Input Document image, legal text, or benchmark sample enters the objective runner.
2. Preprocess Resize, tokenize, normalize, or extract fields depending on the task.
3. Inference Run the classifier, detector, OCR engine, or summarizer candidate.
4. XAI Produce Grad-CAM, bbox annotations, OCR confidence views, or clause highlights.
5. Select Score candidates, write the report, and persist the best objective choice.

Per-Objective Pipelines

These cards mirror the four objective branches in evaluate_objectives.py and the selections stored in generated/objective_selections.json.

Signature Classification

Best model: CNN or ViT signature classifier.

macro_f1 + xai
  • InputSignature image is loaded from the classifier dataset or upload.
  • PreprocessGray or RGB transform is applied, then the image is resized and normalized.
  • InferenceThe selected CNN or ViT predicts real vs fake and returns class probabilities.
  • ExplainGrad-CAM or a similar attribution view highlights the regions driving the prediction.
  • JudgeLLM judge checks confidence alignment, consistency, and overconfidence.
  • OutputBest model path and xai_llm_score are saved into the objective registry.

Signature Detection

Best detector: YOLO signature region model.

f1 + xai
  • InputUploaded page or scan image enters the signature detector branch.
  • PreprocessThe image is resized and prepared for the YOLO inference pipeline.
  • InferenceDetector returns boxes, classes, and confidences for signature regions.
  • ExplainAnnotated overlays show the predicted regions and their bounding boxes.
  • JudgeLLM judge checks localization quality and whether confidence matches the box quality.
  • OutputBest weights and evaluation metrics are written to the report and selections file.

OCR

Best engine: tesseract, paddle, or easyocr by consensus.

consensus_f1 + xai
  • InputDocument image is sent through the OCR branch with sample images or user uploads.
  • PreprocessEach engine normalizes the image and extracts token-level text candidates.
  • InferenceMultiple OCR engines produce text and confidence scores for comparison.
  • ExplainOCR overlays and confidence summaries expose readable vs noisy regions.
  • JudgeLLM judge scores readability, confidence calibration, and token noise.
  • OutputThe registry stores the primary OCR engine and the report keeps the consensus score.

Summarization

Best strategy: rule based, local LLM, or hybrid summarizer.

combined_score + rouge
  • InputLegal text or benchmark document is routed into the summarization benchmarks.
  • PreprocessClauses, entity hints, and expected summary terms are prepared for scoring.
  • InferenceThe summarizer generates a concise summary or clause-level abstraction.
  • ExplainHighlight evidence, clause coverage, or key-term coverage to show why the summary was chosen.
  • JudgeROUGE-L, term recall, and the LLM judge score faithfulness and completeness.
  • OutputThe selected strategy and score are persisted for downstream document workflows.
